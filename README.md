# H&M Personalized Fashion Recommendations - Kaggle

本仓库整理了 Kaggle 竞赛 **H&M Personalized Fashion Recommendations** 的参赛方案与实验流程，目标是基于 H&M 用户历史购买行为、商品属性和时间序列信号，为每位用户推荐未来一周最可能购买的 12 件商品。方案最终获得 **139th / 2304 (Top 6%) - 银牌**。

> 详细参赛方案见根目录 [`readme.pdf`](readme.pdf)。当前仓库以 notebook 形式保留主要流程：数据获取、特征处理、训练与推理。

## 项目竞赛介绍 / 方案分享

### 1. 竞赛简介

**竞赛目标**

根据用户历史购买数据、用户画像与商品元信息，预测每位用户在未来一周内最可能购买的 **12 件商品**，并按购买概率从高到低排序输出。

**评估指标**

竞赛使用 **MAP@12（Mean Average Precision at 12）** 作为评估指标。该指标关注推荐列表前 12 个结果的命中情况与排序质量，越靠前命中真实购买商品，得分越高。

```text
Metric: MAP@12
Task: For each customer, rank the 12 most likely articles to buy in the next 7 days.
```

**数据概况**

| 文件 | 内容 | 数据量级 |
| --- | --- | --- |
| `articles.csv` | 商品基础信息，包括商品 ID、品类、颜色、部门、描述文本等 | 约 10 万商品，实际建模中活跃商品约 3 万 |
| `customers.csv` | 用户画像，包括用户 ID、年龄、会员状态、活跃状态等 | 约 137 万用户 |
| `transactions_train.csv` | 历史交易明细，包括用户、商品、交易日期、价格、渠道等 | 约 3,000 万条交易记录 |
| `sample_submission.csv` | 提交格式样例 | 每位用户 12 个推荐商品 |

### 2. 核心挑战

1. **极度稀疏的用户-商品交互矩阵**：用户数和商品数都很大，但单个用户的购买记录有限，直接建模交互矩阵会面临严重稀疏问题。
2. **冷启动问题**：新用户历史行为不足，新商品缺少交互反馈，需要依赖用户画像、商品属性、流行度和近期趋势进行补充。
3. **时间序列特性明显**：服装购买行为受季节、上新周期、促销节奏和用户复购周期影响，近期行为通常比早期行为更重要。
4. **类别不平衡**：热门商品获得大量曝光与购买，长尾商品样本极少，模型容易偏向高频商品，影响个性化与召回覆盖。

### 3. 解决方案概览

整体方案采用 **候选集召回 + 排序模型精排 + 多模型融合 + 后处理** 的推荐系统范式。先通过热门商品、用户历史复购、协同过滤和向量召回生成候选商品，再使用排序模型预测用户-商品购买概率，最后融合多个模型结果并进行规则修正。

#### 特征工程

**用户历史行为统计**

- 用户历史购买次数、购买天数、活跃周期、最近一次购买距预测窗口的天数。
- 用户近期购买强度，例如最近 7 / 14 / 30 天购买次数和消费金额。
- 用户价格偏好，包括平均购买价格、价格分位数、最高/最低购买价格、价格波动。
- 用户渠道偏好，例如线上/线下购买比例。

**商品属性特征**

- 商品品类、颜色、图案、部门、产品组等结构化属性。
- 商品历史销量、近期销量、购买用户数、复购率、流行度趋势。
- 商品价格统计，包括均价、价格分位数、折扣或价格变化信号。
- 商品描述文本特征，使用 TF-IDF 表示描述文本，辅助捕捉相似商品关系。

**交叉特征**

- 用户年龄段与商品品类偏好。
- 用户历史购买品类与候选商品品类是否匹配。
- 用户价格区间偏好与候选商品价格区间的匹配程度。
- 用户近期购买商品与候选商品在品类、颜色、描述文本上的相似度。

#### 模型架构

| 模型 | 作用 | 验证集表现 |
| --- | --- | --- |
| ALS 协同过滤 | 基于用户-商品隐式反馈进行召回，补充个性化候选 | 基模型 |
| LightGBM Ranker | 对召回候选进行精排，利用大量统计特征和交叉特征 | **0.0385** |
| Two-Tower 双塔模型 | 用户塔与商品塔分别学习向量表示，通过内积计算匹配度 | **0.0412** |
| 融合模型 | 结合排序模型、双塔模型、协同过滤和热门召回结果 | **0.0458** |

**Two-Tower 双塔模型**

- 用户塔输入用户画像、历史购买序列聚合特征和价格偏好。
- 商品塔输入商品属性、文本向量、价格特征和流行度特征。
- 通过用户向量与商品向量内积计算相似度，用于向量召回与排序分数补充。

**LightGBM 排序模型**

- 先生成用户级候选集，再构造用户-商品样本。
- 使用时间切分验证集模拟线上预测窗口。
- 以用户为 group 训练排序目标，学习候选商品在用户维度下的相对顺序。

**ALS 协同过滤**

- 将购买行为视为隐式反馈。
- 使用购买次数、近期权重或时间衰减权重构造交互强度。
- 作为召回基模型，尤其适合补充用户历史偏好的相似商品。

#### 融合策略

- 对 LightGBM、Two-Tower、ALS、热门商品和复购规则的输出进行 **加权平均**。
- 使用 **Rank averaging** 降低不同模型分数尺度不一致带来的影响。
- 在本地验证集上搜索或学习最优融合权重，最终选择兼顾验证分数与线上稳定性的组合。

#### 后处理

- 对商品流行度进行平滑，避免短期爆款过度主导推荐列表。
- 对每位用户的推荐结果去重，保证输出 12 个唯一商品。
- 根据实验设置可选择去掉用户已购买过的商品，减少重复推荐；对强复购品类则保留复购候选并通过排序模型决定位置。
- 对候选不足 12 个的用户，使用近期热门商品和分年龄段热门商品补齐。

### 4. 实验结果与成绩

| 方案 | 验证集 MAP@12 | 说明 |
| --- | ---: | --- |
| LightGBM 单模型 | **0.0385** | 候选集生成 + 特征精排 |
| Two-Tower 双塔模型 | **0.0412** | 用户塔 + 商品塔向量匹配 |
| 多模型融合 | **0.0458** | 加权平均 + Rank averaging + 后处理 |

### 5. 经验总结与可复现性

**最重要的三个提分点**

1. **高质量候选集生成**：热门商品、用户历史复购、相似商品召回、ALS 和双塔向量召回互补，显著提高真实购买商品的召回率。
2. **负样本采样策略**：按照时间窗口构造训练样本，控制正负样本比例，并优先保留高质量难负样本，使排序模型更贴近线上任务。
3. **模型融合与后处理**：不同模型捕捉的信号不同，LightGBM 擅长表格特征，双塔模型擅长相似度学习，ALS 擅长协同信号，融合后稳定提升 MAP@12。
